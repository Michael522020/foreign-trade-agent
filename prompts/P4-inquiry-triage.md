# P4 — 询盘分级与跟进节奏

> 前置检查：`Inquiry` 表已存在，且有真实询盘数据 ≥ 30 条（去平台后台导出即可）。
> 没有真实数据不要做这一步——询盘分类规则只能从真实语料里长出来。

## 目标

把询盘分成六类，判断"这封值不值得业务员 10 分钟"，并生成下一步动作（含时间点和话术要点）。

## 第一步：先量一下基线

在做任何分类之前，先跑：

```bash
python -m src.cli inquiry stats --source platform_exports --since 2025-10-01
```

必须产出这几个数（没有就先人工数，不要猜）：

| 指标 | 为什么要它 |
|---|---|
| 月均询盘量 | 决定业务员负荷，也决定"漏一条"的代价 |
| 首响应时长中位数 | 行业里 4 小时内响应，超过 24 小时转化率断崖 |
| 有效询盘占比 | 如果 <30%，说明渠道本身有问题，不是分类算法的问题 |
| 询盘→报价 转化率 | 衡量分级质量的核心指标 |
| 报价→订单 转化率 | 衡量报价与跟进质量 |

**这些数就是后面所有"提升了多少"的基线。没有基线就没有优化，只有感觉。**

## 分类规则

规则优先，LLM 兜底。**不要反过来。**

```python
def classify(inquiry: Inquiry) -> InquiryType:
    # 1. 硬规则（确定性，先跑）
    if inquiry.lead is existing_customer:      return EXISTING_CUSTOMER
    if looks_like_mass_blast(inquiry):         return SPAM_BLAST
    if domain_matches_competitor(inquiry):     return COMPETITOR_PROBE
    if asks_for_sample_only(inquiry):          return SAMPLE_REQUEST
    # 2. 结构化判定
    filled = count_of_5_elements(inquiry)   # 数量/规格/目的地/交期/目标价
    if filled >= 3:                            return REAL_RFQ
    return PRICE_PROBE
```

只有 `COMPETITOR_PROBE` 和 `SPAM_BLAST` 允许用 LLM 辅助判断（语义相似度），且必须给出触发理由，允许人工改判。

### 五要素提取

从正文里抽：`quantity` / `spec` / `destination` / `lead_time` / `target_price`。
抽不到就是 `None`，**不要用 0 或默认值填充**。抽不到的项进 `missing_info[]`，直接变成回复里的提问。

### 时效分级

| 类型 | 首响应 SLA | 理由 |
|---|---|---|
| `REAL_RFQ` | 2 小时 | 有明确需求，晚一步就被比价方截走 |
| `SAMPLE_REQUEST` | 4 小时 | 打样是信任建立的关键动作 |
| `EXISTING_CUSTOMER` | 4 小时 | 老客户优先级高于新客 |
| `PRICE_PROBE` | 24 小时 | 需要时间查资料再回，但要用提问换信息 |
| `COMPETITOR_PROBE` | 48 小时 | 只给公开区间 |
| `SPAM_BLAST` | 不响应 | 归档 |

## 回复生成（不是自由发挥，是填空）

`PRICE_PROBE` 的回复结构（这是最基本的、也是最常被做错的一步）：

```
1. 感谢 + 一句表示理解其需求（不给价）
2. 提 1 个专业问题（证明你懂这行）
3. 索取缺失的 5 要素（列成清单，方便客户照填）
4. 给一个范围而不是价格（如 "typically USD 2.6-3.4/pc depending on qty and finish"）
5. 承诺明确下一步时间（如 "I'll send a formal quote within 24h once I have the qty"）
```

**关键**：第 4 步给区间而不是精确价，是为了不被拿去当比价锚点；第 5 步给承诺时间，是为了把节奏握在自己手里。

业务规则：
- 不在首封给精确单价（除非客户 5 要素齐全）
- 不在邮件里给成本结构、供应商信息、模具报价细项
- 涉及 `DP/DA/OA` 付款要求 → 立即转人工，模板不回应
- 客户提到"我们也在和 XX 谈" → 不贬低同行，只强调差异点

## 跟进节奏（这是外贸最讲纪律的地方）

按询盘进入后的天数：

| 时点 | 动作 | 谈什么 |
|---|---|---|
| D0 | 首响应 | 确认需求 + 提问 |
| D1–3 | 报价（若信息齐） | 报价单 + 技术资料 |
| D4–7 | 首次跟进 | **不谈价格**，谈工艺、品控、同行案例 |
| D8–15 | 推样品/视频验厂 | 把客户从"比价"拉到"体验" |
| 样品签收日 | 确认收到 | 问测试安排 |
| 签收后 D3 | 问测试反馈 | 具体问题 |
| 签收后 D7 | 未反馈则跟进 | 提供替代方案 |
| D31–45 | 谈条款 | 付款方式、交期、验货方式 |
| 成交后 | 每周发生产进度照片 | 客户已付定金，需要确定性 |

**三个高危断点**（系统必须主动提醒，不能靠业务员记性）：
1. **报价后 7 天无动静** → 不要发"考虑得怎么样"，改发价值邮件（新品/案例/行业动态）
2. **样品签收后无反馈** → 样品可能没到实际使用人手里，要问"是否需要我们再寄一份给技术团队"
3. **合同发出后未回签** → 大概率是条款卡住，要拆开逐条问，不要整体催

**"客户在往前走"的信号**：问题越来越细（从"多少钱"到"能不能做定制包装"）。
**"客户在退"的信号**：回复越来越短、问题越来越泛、开始问"你们最小起订量能不能再低"。

这两个信号要做成系统里的标记，不能只写在员工的脑子里。

## 验收

```bash
python -m pytest tests/inquiry/ -v
python -m src.cli inquiry triage --since 2026-10-01 --dry-run
```

必须覆盖：
1. 只有"请报价"三个字的询盘 → `PRICE_PROBE`，`missing_info` 含全部 5 项
2. 竞对域名发来的询盘 → `COMPETITOR_PROBE`，回复中不含成本/供应商信息
3. 客户要求 `OA 60 days` → 状态标 `NEEDS_HUMAN`，模板不生成
4. 报价后第 7 天 → 生成价值邮件任务，而非催促
5. 询盘→报价→订单 漏斗按周统计，可导出

## 不要做的事

- 不要把 `PRICE_PROBE` 自动归档。外贸里大量真实订单第一封就是只问价，自动丢弃等于主动放弃线索。
- 不要让 LLM 直接写完整回复发送。生成草稿，人审。
- 不要用"回复率"作为唯一优化目标。追问细节的回复比"thanks"更有价值，要有质量分级。
- 不要在系统里内置价格。所有价格来自 `Quotation` 流程。
